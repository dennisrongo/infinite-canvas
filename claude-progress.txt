Implementation Overview:
-----------------------

Added comprehensive rate limiting to canvas creation endpoint:

1. Rate Limit Configuration (src/lib/rate-limit.ts):
   - Added `canvasCreation` config:
     * limit: 10 requests per minute
     * windowMs: 60,000ms (1 minute)
     * blockDurationMs: 300,000ms (5 minutes)

2. Canvas Endpoint Updates (app/api/canvases/route.ts):
   - Imported rate limiting utilities
   - Applied checkRateLimit() to POST endpoint
   - Added rate limit headers to all responses:
     * X-RateLimit-Limit: 10
     * X-RateLimit-Remaining: (decrementing counter)
     * X-RateLimit-Reset: (ISO timestamp)
   - Returns 429 status when limit exceeded
   - Includes Retry-After header in error response

3. Error Messages:
   - Below limit: Normal operation with rate limit headers
   - Limit exceeded: "Rate limit exceeded. Please try again in X seconds."
   - After block: "You have been temporarily blocked due to excessive canvas creation. Please try again in X seconds."

4. Rate Limit Headers (added to ALL responses):
   - X-RateLimit-Limit: Maximum requests allowed
   - X-RateLimit-Remaining: Requests remaining in window
   - X-RateLimit-Reset: When window resets (ISO 8601 timestamp)
   - Retry-After: Seconds until retry allowed (429 responses only)

5. User Identifier:
   - Uses IP address from headers (x-forwarded-for, x-real-ip, cf-connecting-ip)
   - Falls back to 'unknown' if no headers present
   - Same rate limit applied per IP address
