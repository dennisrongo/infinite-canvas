Implementation Overview:
-----------------------

Added comprehensive URL security validation:

1. New validation utilities in src/lib/validation.ts:
   - isValidUUID(id: string): boolean
     Validates UUID format (8-4-4-4-12) to prevent path traversal
     Returns false for strings like "../../../etc/passwd", "OR 1=1", etc.

   - sanitizeUrlParam(param: string): string | null
     Checks for path traversal attempts (.., \, /)
     Checks for URL-encoded path traversal (%2e%2e, %5c)
     Returns null if invalid, sanitized param if valid

   - isSafeRedirectUrl(redirectUrl: string): boolean
     Only allows relative URLs starting with /
     Prevents protocol-relative URLs (//evil.com)
     Prevents javascript: and data: URLs
     Validates safe character set

   - uuidSchema: Zod schema for UUID validation

2. Updated ALL API routes with UUID validation:
   - app/api/canvases/[id]/route.ts (GET, PUT, DELETE)
   - app/api/canvases/[id]/notes/route.ts (GET, POST)
   - app/api/canvases/[id]/connections/route.ts (GET, POST)
   - app/api/notes/[noteId]/route.ts (PUT, DELETE)
   - app/api/notes/[noteId]/duplicate/route.ts (POST)
   - app/api/notes/[noteId]/images/route.ts (POST)
   - app/api/connections/[id]/route.ts (DELETE)
   - app/api/folders/[id]/route.ts (PUT, DELETE)
   - app/api/images/route.ts (POST)

3. Security pattern added to each route:
   

4. Existing security measures confirmed:
   - User ownership checks (userId validation) on all routes
   - Session-based authentication with JWT tokens
   - Prisma ORM with parameterized queries (SQL injection prevention)
   - UUID-based IDs (harder to guess than sequential IDs)

Attack Vectors Prevented:
